# math-olympics

Тренажёр подготовки к математической олимпиаде **SASMO** — программа на 28 дней
с ежедневными наборами задач, пробными экзаменами и журналом ошибок.
Два класса, у каждого своя программа и свои 330 задач:

| Класс | Хаб | Одним файлом | Программа |
|---|---|---|---|
| **Grade 3** | `index.html` | `sasmo-month.html` | [ПЛАН.md](ПЛАН.md) |
| **Grade 2** | `index.html?g=2` | `sasmo-month-2.html` | [ПЛАН-2.md](ПЛАН-2.md) |

**Запуск:** откройте `index.html` двойным кликом и выберите класс вкладкой в
шапке. Локальный сервер не нужен — всё работает по протоколу `file://`.

**На телефоне** задачи показываются **по одной на экран**: листать можно
свайпом, стрелками внизу или из карты задач — она же показывает, сколько
осталось без ответа, и возвращает к пропущенным на втором проходе. На
широком экране по умолчанию обычный список; переключатель «По одной /
Списком» стоит над задачами, и выбор запоминается. Это только способ
показа — ответы, подсказки, разборы, таймер, счёт и журнал ошибок в обоих
видах одни и те же.

Прогресс классов хранится **раздельно**: за тренажёром сидят разные дети, и один
не может стереть или перебить результаты другого.

Одностраничные сборки — весь тренажёр в одном файле, их удобно отправить или
открыть на планшете. Собираются командой `node build/build.js` из тех же данных,
что и многостраничная версия.

**Рисунки к задачам:** [КАРТИНКИ.md](КАРТИНКИ.md)

## Таблица умножения на скорость (Grade 2)

`mult.html` — кнопка «⚡ Таблица умножения на скорость» на хабе второго класса.
Пример и четыре варианта ответа, на каждый пример — 10, 6 или 4 секунды.
Этого хватает, чтобы **вспомнить** ответ, но мало, чтобы досчитать сложением.
Не успел — считается ошибкой, правильный ответ показывается сразу.

- Столбики (×2 … ×10) и длина раунда выбираются перед стартом.
- Неверные варианты правдоподобные: соседи по таблице (7×8 → 7×7, 6×8) и числа
  той же чётности, чтобы ответ не угадывался по «лишнему» числу.
- Статистика ведётся по каждому примеру (7×8 и 8×7 — один пример): ошибки и
  медленные ответы попадаются в следующих раундах чаще. **Карта таблицы**
  показывает, какие примеры выучены (дважды подряд быстрее 3 с), какие
  вспоминаются долго и в каких были ошибки.
- После раунда можно отдельно прорешать трудные примеры.
- Хранится под ключом `sasmo.g2.mult` и в журнал ошибок занятий не попадает.
  В одностраничную сборку `sasmo-month-2.html` тренажёр не входит.

## Олимпиады прошлых лет

Кроме программы на 28 дней в репозитории лежат целые прошлые олимпиады —
их дают на курсах и решают целиком, а не по дням. На хабе они собраны в
раздел **«Олимпиады прошлых лет»**, по карточке на олимпиаду:

| Работа | Страница | Формат |
|---|---|---|
| **SASMO 2025**, 3 класс | `paper.html?p=sasmo25` | 25 задач, 90 минут, максимум 85 баллов |
| **SASMO 2024**, 3 класс | `paper.html?p=sasmo24` | 25 задач, 90 минут, максимум 79 баллов |
| **SASMO 2023**, 3 класс | `paper.html?p=sasmo23` | 25 задач, 90 минут, максимум 83 балла |
| **MathXCEL 2024**, 3 класс | `paper.html?p=mathxcel24` | 25 задач, 80 минут, максимум 55 баллов |
| Тест Коперника (архив) | `copernicus.html` | старая отдельная страница |

Счёт у SASMO такой же, как у пробных экзаменов программы (секция A по 2 балла
со штрафом −1, секция B по 4 без штрафа, 15 баллов на старте), поэтому наборы
`data/sasmo25.js`, `sasmo24.js` и `sasmo23.js` своих правил не несут —
работают правила движка по умолчанию. У MathXCEL счёт другой: часть 1 (задачи 1–20) по 2 балла, часть 2
(задачи 21–25) по 3 балла, **штрафов нет ни в одной части** — значит пустых
ответов быть не должно. Такие правила лежат не в движке, а в самом наборе
задач, в поле `rules` (см. `data/mathxcel24.js`).

У SASMO **пять вариантов ответа**, и пятый — «ничего из перечисленного».
Это не формальность: в работе 2025 года он верен один раз (задача 11), а в
работе 2024 — дважды (задачи 7 и 12). Считать нужно до конца и только потом
смотреть в список вариантов, а не наоборот.

### Задачи без восстановленного ответа

Буклеты прошлых олимпиад идут **без ключа**, поэтому каждый ответ в наборе
посчитан заново — ход решения стоит рядом, в поле `ex`. К трём задачам ответ
восстановить не удалось, и тренажёр его **не придумывает**: у задачи стоит
поле `skip`, условие и рисунок видны, а в счёт она не идёт.

| Задача | Почему без ответа |
|---|---|
| SASMO 2024, №13 | пятиугольники с числами: ни одна формула от двух нижних чисел не даёт всех четырёх данных значений |
| SASMO 2024, №25 | сетки с сердечками: веса клеток не сходятся ни при одной разумной разметке |
| SASMO 2023, №6 | пирамида из кубиков нарисована с перспективой, а варианты отличаются на один кубик |

Из-за этого максимум работы меньше 85: у SASMO 2024 — 79 баллов, у SASMO
2023 — 83. Движок считает его сам, по числу задач без `skip`, так что «85
из 85» за неполную работу ребёнку не покажут. Если ключ найдётся — достаточно
убрать `skip` и дописать `ans`, `hint` и `ex`.

### Как добавить прошлую олимпиаду

Отдельная страница не нужна — все работы открывает одна `paper.html`,
а список берёт из каталога `window.PAPERS` в `assets/paper.js`:

```js
{ id: 'sasmo25',  olympiad: 'SASMO', year: 2025, grade: 3,
  set: 'sasmo25', varName: 'SASMO25', minutes: 90, max: 85,
  note: '25 задач · 90 минут · счёт как на пробных экзаменах' }
```

Дописать строку сюда, положить рядом `data/<set>.js` — и карточка сама
появится на хабе того класса, который указан в `grade`. Набор задач
устроен так же, как дни программы (см. «Как добавить набор задач»);
английский оригинал условия едет в поле `en` и показывается по `?lang=en`.

### Двое за одной работой

За прошлые олимпиады садятся двое, и **прогресс у каждого свой** — отдельные
ключи хранения и отдельный журнал ошибок:

| | прогресс | журнал ошибок |
|---|---|---|
| Дима | `paper.dima.progress` | `paper.dima.errors` → `errors.html?who=dima` |
| Богдан | `paper.bogdan.progress` | `paper.bogdan.errors` → `errors.html?who=bogdan` |

Ни один из них не пишет в `sasmo.progress`: работа живёт вне 28-дневной
программы, и ошибки из неё не мешаются с ошибками занятий. Журнал у решающего
**один на все работы** — поэтому из него возвращаются не на страницу одной
олимпиады, а в раздел олимпиад на хабе.

Задачи при этом **общие**: обоим достаётся один и тот же `data/<set>.js`,
25 задач не дублируются. Кто решает — выбирается на самой странице
(`paper.html?p=sasmo25` спрашивает, `paper.html?p=sasmo25&who=dima` открывает
сразу). Страницы `mathxcel_dima.html` и `mathxcel_bogdan.html` остались как
были — на них ведут старые ссылки, и прогресс у них тот же.

Добавить третьего решающего — дописать его в `window.SOLVERS`
(`assets/paper.js`); ни страницы, ни каталог работ править не нужно.

## Как сохраняется прогресс

Одинаково в обеих версиях — и в многостраничной, и в `sasmo-month.html`.

Сохраняется **каждый ответ по отдельности**, а не только пройденный целиком
день: ребёнок может решить пять задач из десяти, закрыть страницу и вернуться
к остальным вечером — решённое останется на месте. То же и с экзаменом:
начатая попытка помнит и ответы, и оставшееся время, а страница предлагает
её продолжить.

Сбросить можно как весь прогресс (кнопка внизу хаба), так и **один день** —
кружок со стрелкой в углу карточки дня или кнопка на самой странице занятия.
Сброс дня убирает и его задачи из журнала ошибок. Обе кнопки требуют нажать
дважды: слишком обидно стереть месяц работы случайным касанием.

## Как добавить набор задач

Данные лежат в `.js`, а не в `.json`: на `file://` браузер блокирует `fetch`, а
подключение `<script>` работает.

```js
window.DAY08 = {
  intro: { title: 'Приём дня', body: '<p>…</p>' },
  questions: [
    { type: 'mcq',  topic: 'Закономерности', q: 'Продолжи ряд: 2, 5, 9, 14, ?',
      opts: ['18','19','20','21'], ans: 2, hint: 'Выпиши разности.', ex: 'Разности растут на 1 → 20.' },
    { type: 'open', topic: 'Закономерности', q: 'Сколько…?',
      ans: 42, hint: '…', ex: '…' }
  ]
};
```

У `mcq` поле `ans` — индекс верного варианта (0–3, а в работах SASMO 0–4:
там пять вариантов), у `open` — само число.
Необязательные поля `fig` и `exfig` добавляют рисунок к условию и к разбору —
см. [КАРТИНКИ.md](КАРТИНКИ.md).
Готовые наборы перечисляются в массиве `ready` в `assets/plan.js` (для второго
класса — в `assets/plan2.js`): пока набора там нет, хаб гасит карточку дня,
чтобы не вести на пустую страницу.

Наборы второго класса лежат в `data/g2/` и объявляют переменные с приставкой
`G2`: `window.G2DAY08 = { … }`.

После правки задач:

```
node build/check.js      # задач столько, сколько обещано; ответы сходятся с разбором
node build/build.js      # пересобрать sasmo-month.html и sasmo-month-2.html
```

После правки движка или вёрстки задач:

```
npm install --no-save jsdom   # один раз
node build/uitest.js          # режим «по одной» и раздельный прогресс на месте
```

`sasmo-month.html` несёт **собственную копию движка** — она не берётся из
`assets/quiz.js`, а живёт в `build/template.html`. Правку поведения нужно
вносить в оба места, и `build/uitest.js` прогоняет обе версии именно
поэтому: молча разойтись они могут очень легко.

## Проверка ответов математикой

`build/check.js` смотрит на структуру набора, но само число берёт на веру:
если в условии «60 ÷ 12», а в `ans` стоит 6, он промолчит. `tools/verify.py`
считает ответ заново — символьной математикой через **sympy**.

```
pip install -r tools/requirements.txt
python tools/verify.py               # проверить наборы
python tools/verify.py --strict      # задача без проверки — тоже ошибка
```

Задача носит доказательство рядом с собой, в двух необязательных полях:

```js
/* ответ — число: считаем его из условия */
{ type: 'open', ans: 5, check: 'solve(Eq(12*L, 60), L)[0]' }

/* ответ — утверждение: проверяем каждый вариант отдельно */
{ type: 'mcq', ans: 2,
  opts: ['9 876 > 8 765', '14 321 < 15 432', '13 567 > 13 678', '6 543 > 5 432'],
  optcheck: ['9876 > 8765', '14321 < 15432', '13567 > 13678', '6543 > 5432'],
  optpick: 'false' }          // верен тот вариант, чьё утверждение ложно
```

С `optcheck` проверка требует, чтобы подходил **ровно один** вариант и чтобы
это был `ans`. На этом и ловится дефект исходной работы MathXCEL 2024: в
задаче 13 там ложны сразу два сравнения, а выбрать просят одно (в наборе
вариант D исправлен, в файле об этом стоит комментарий).

Задачи, где ответ вообще не математический — «в чём измеряют бензин», — в
отчёте перечислены отдельно как непроверяемые, а не помечены как сошедшиеся.
